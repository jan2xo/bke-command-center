# Installation-scoped inactive registration audit projection — SOURCE ONLY

Parent: [Command Center issue #30](https://github.com/jan2xo/bke-command-center/issues/30). Depends on merged Command Center #56 inactive pairing and Worker [#112](https://github.com/jan2xo/bke-worker/pull/112) / [#113](https://github.com/jan2xo/bke-worker/pull/113) multi-worker ownership and GitHub inventory audit.

The protected pairing finalizer stores a real installation-scoped `paired` array inside the SQLite-backed `BkeWorkerPairingVault`. Registration rows have exactly the worker ID, P-256 identity SHA-256, three owner-pinned resource SHA-256 values, one pairing nonce SHA-256, status, registration time and enrollment expiry. **They do not contain a verified live session binding.** The #112 multiworker scheduler audit additionally needs `session_binding_sha256`, and must never synthesize it from the pairing nonce, a PR body, browser profile claims, or other credentials.

`src/admin-inactive-registration-audit.js` adds a **dormant server-private, transactionally consistent, read-only projection** of existing paired-vault registration state. The trusted host must supply its installation-scoped `createPairingAtomicStore` instance and a separately verified, private, owner-resolved installation ID (not from browser/HTTP JSON). The projection validates the *complete registry*, including REVOKED rows, before selecting live unexpired `PAIRED_INACTIVE` rows; duplicate IDs/resources, malformed/future/expired records, unexpected keys and uncertain reads fail closed. It returns a minimal immutable set of four resource hashes and worker IDs, with explicit `session_binding_authority=NONE`, `dispatch_authority=NONE`, `wake_authority=NONE`, `pairing_activation=NONE`.

No Durable Object RPC, HTTP/WebSocket, GitHub App token, pairing mutation or Cloudflare environment flag is introduced. `BkeWorkerPairingVault` and deployable entrypoints intentionally DO NOT call this helper yet; hooking it into an authenticated, installation-matched read-only DO RPC requires a distinct intent and certification. Before the Worker #112 consistency audit may consume any record as a *verified active registration*, the system must additionally prove actual authenticated OS/browser session, private server transport, fresh exclusive session binding, live registry status and installation scope. This snapshot is **not** that certification.

Certify with real in-memory transactional store tests including read serialization and registry adversarial fixtures, exact-head Command Center CI: Node tests, npm check, Wrangler PREPRODUCTION dry-run and local Workerd/SQLite smoke. No production/PREPRODUCTION mutation, live pairing, device dispatch, browser permissions, Android wake or enrollment.

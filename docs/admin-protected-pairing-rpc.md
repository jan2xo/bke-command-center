# Protected installation-bound inactive pairing RPC — source-only

**Status: DORMANT, default OFF, not deployed.** Parent: [Command Center issue #30](https://github.com/jan2xo/bke-command-center/issues/30). Depends on merged Command Center #39–#47 and BKE Worker #104. This PR connects the existing atomic inactive-pairing finalizer to a **named, non-HTTP Durable Object RPC**. It does **not** provide a public device enrollment API, active PR/worker lease or production permission.

## Strict trust path

`sendProtectedInactivePairing` executes only as **trusted Command Center server code**. It refuses every flag not exactly enabled (`BKE_PREPRODUCTION`, verified Access policy, private GitHub PR inventory, pairing action, DO routing, protected inactive pairing, and independent `BKE_ADMIN_PROTECTED_RPC_ENABLED`). This last flag and the shared `BKE_PAIRING_RPC_KEY_B64` key are **absent** from Wrangler; no secret is provisioned in this wave. It validates the P-256 signature/proof shape and checks platform-provided `executionCtx.access` against the exact app AUD and human Admin allowlist. It then derives an opaque, deterministic **HMAC-keyed human subject** from the platform identity. Do not accept a browser-supplied email, role, fingerprint, installation ID or `authorized:true` instead of these checks.

The caller obtains the installation ID through the **private Worker broker's complete, strict read-only GitHub PR assignment inventory**, never a UI-selected tenant. It creates a 256-bit CSPRNG nonce with 30-second expiry, cryptographically seals the entire normalized device proof, one-time Admin nonce, opaque human subject, installation ID, expiry and operation/purpose via a versioned, domain-separated HMAC-SHA256 message, and calls only the trusted `BKE_WORKER_PAIRING_VAULT.get(idFromName('installation:'+installationId)).finalizeProtectedInactivePairing` named RPC. The entire authenticated envelope is server-to-DO only; never put it in PR comments, logs or browser responses. The caller returns only fixed redacted `BLOCKED` or `PAIRED_INACTIVE` codes.

The Cloudflare DO subclass and Node-testable vault logic export that **single newly added protected operation** (plus the prior read-only `attestInstallation` and 404 `fetch`). Inside the DO, the envelope must pass strict exact-schema, purpose, operation, time window, HMAC, and actual `ctx.id`/installation namespace checks before ANY broker lookup or atomic state write. Verified HMAC creates a **locally branded internal context**, not a forged Cloudflare Access object. The protected finalizer retains platform Access validation by default for normal use; only this cryptographically checked DO path injects an explicit `authorizeAccess` closure accepting that exact local context. The HMAC-sealed subject fingerprint is used with the same Admin ticket binding. The DO independently requests a **new** GitHub App PR inventory through its existing private broker, validates it with the exact same `parseTrustedWorkerAssignmentPayload` schema the human Admin reader uses, and checks installation scope/worker ownership before invoking the original protected inactive finalizer.

The finalizer's **one installation-wide storage transaction** validates the human Admin ticket and signed device challenge and writes all three changes: inactive paired identity, removal of the pending device challenge and consumption of the human ticket. A failed third write rolls back the other two. Racing/replayed signed envelopes cannot register more than once because the human ticket/device challenge are consumed in that atomic transaction. A timeout or missing response remains **UNKNOWN** to the caller; do not retry an active action blindly without checking durable state. This code returns only `PAIRED_INACTIVE`; it never issues worker credentials, an active lease, or a PR label.

## Security boundaries still locked

1. The server helper is **not imported by any public HTTP handler**. It has no human UI, origin/CSRF one-use consent route or protected user action endpoint. It must not be called from an arbitrary browser-provided JSON body; a later independently certified per-action consent/transport PR must connect it to the human ticket issuer, P-256 device challenge issuer, and actual authenticated device bridge.
2. The human HMAC subject derivation used in this RPC must match the subject derivation used when issuing a one-use Admin ticket. This PR does not expose the ticket issuance or device challenge through the DO RPC. Tests initialize them through the existing source modules. A later intent must couple issuance and consent under the same backend-derived subject.
3. GitHub's `NON_ATOMIC_ENUMERATION` is an observation, NOT a cross-repository lock. The finalizer rejects observed pre-existing worker assignments, but a PR label can change after the read. This code must NOT authorize actual worker wake or access to a shared ChatGPT target/browser profile. Lease/isolation authority is a separate GitHub-exact-head claim and worker runtime certification.
4. A 30-second signed command's nonce is not separately stored; it may be retransmitted within its TTL, but its **one-use ticket and device challenge** prevent duplicate successful registration. Denied/replayed attempts have no persistent side effects.
5. The protected pairing feature is **OFF**. The source CI/test doubles are not real Cloudflare Access authentication, GitHub provider grants, named DO remote RPC, live SQLite persistence or human/device pairing proof. No Cloudflare secret writes, feature activation, GitHub App permission changes, worker wakes, security challenge automation, Android parked PR #90 continuation or production deployment are authorized.

Source certification: full exact-head Command Center `ci` (all Node tests and syntax checks, Wrangler PREPRODUCTION dry-run), explicit negative identity/tenant/HMAC/rollback/replay tests and bounded security review. Minimum follow-on: authorize bounded PREPRODUCTION live Cloudflare DO/Access/GitHub-read acceptance and implement authenticated device command issuance and active-lease recovery as **separate fresh PRs**. GitHub remains durable task truth; the DO stores only bounded pairing identity/proofs, not a second planner.

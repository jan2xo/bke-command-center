# Decision-time GitHub PR ownership recheck — dormant preflight only

**Status: SOURCE-ONLY; NO HTTP endpoint, no DO RPC, no live pairing.** Dependency chain: [Command Center #30](https://github.com/jan2xo/bke-command-center/issues/30); merged Worker #104, Command Center #39–#44.

`inspectDecisionTimePairingPreflight` is an internal server-only, default-OFF negative-conflict check. With a **platform-authenticated human Admin context**, trusted GitHub App installation identity, already installation-scoped one-time-ticket manager, and the existing private GitHub broker reader, it:

1. Requires explicit PREPRODUCTION/Access/PR-inventory/pair-action/**separate decision-recheck** feature locks, all currently unset for the new path.
2. Validates the caller-supplied-to-internal-code installation ID and the one-time ticket format; no installation ID, worker ID, token or adapter is accepted from a new browser route (none exists).
3. Performs a fresh GitHub App installation-wide ownership observation using `readAdminWorkerAssignments`, which independently validates the Cloudflare human Access identity, approved scope, unique worker claims, exact PR heads and repository IDs.
4. Rejects any observed existing PR assignment for the candidate worker. Calls the installation-scoped `ticketManager.consume` *exactly once*, binding the same human platform context, worker ID and `pair` action. The ticket manager's trusted `authorizeAdmin` callback MUST verify the human subject and fixed installation, not an untrusted object.
5. Immediately performs another fresh full GitHub observation. Rejects missing/inconsistent installation identity, changed open PR counts, approved-repository count, worker label/PR head/repository identity changes, candidate ownership or elapsed time above 30 seconds. A failed second read **burns** the one-time ticket; no hidden retry, no fallback to stale snapshot, no authorization on ambiguity.

A successful result is `CHECKED_NOT_RESERVED / DECISION_PREFLIGHT_NON_ATOMIC`, with `pairing_authority:NONE` and `dispatch_authority:NONE`. The deliberate choice of a NON-AUTHORIZING result is central. Even two complete reads cannot guarantee that a new PR label was not added milliseconds later, nor can they reserve the worker's ChatGPT target or browser profile. **This is NOT final decision-time exact-head enforcement or a lock**; it is a negative evidence assessment that rejects detected conflicts and races. The future actual pairing operation must independently revalidate exact-head GitHub PR state, enforce one worker ↔ one PR, bind the same installation and human action to the protected operation atomically (or fail closed on uncertain outcome), prove profile isolation and live device key possession, and pass live Cloudflare SQLite DO + PREPRODUCTION human testing.

This code is NOT connected to `src/index.js`, `BkeWorkerPairingVault`, any HTTP handler, live credentials or environment. The `BKE_ADMIN_DECISION_RECHECK_ENABLED` flag is not present in Wrangler. No Admin key/token, installation ID, profile, PR body, raw provider exception, or one-time nonce is returned. No PR mutation, worker wake, Cloudflare rollout, App permission change, OAuth/MFA/CAPTCHA, real device pairing, or production action. Source certification: full exact-head Command Center `ci` and bounded security audit; no unrelated Android/extension/runtime certification.

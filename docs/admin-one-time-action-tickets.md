# Admin one-time human action tickets — dormant atomic dependency

**Status: SOURCE ONLY, no endpoint, no deployment, no worker access.** Program issue: [#30](https://github.com/jan2xo/bke-command-center/issues/30). Depends on merged #39–#43 and Worker #104. GitHub remains the sole durable engineering/PR assignment authority.

The internal `createAdminOneTimeActionTickets` creates a 90-second ticket bound to exact `pair|revoke`, worker ID, trusted installation identity and a human subject fingerprint. An injected **trusted server callback** must verify platform Cloudflare Access identity, exact AUD, allowlist and explicit human action before returning a **keyed opaque human subject digest**. Never derive authority from browser JSON, forwarded headers, a raw email, a bare unsalted email hash, a stored Admin secret, or a test-supplied boolean. The source library cannot itself attest that injected callbacks are trustworthy.

Ticket issue produces a random 128-bit challenge ID and 256-bit nonce via Web Crypto. Only a SHA-256 binding of protocol audience, installation, action, worker, challenge, subject digest and raw nonce is stored. The raw nonce is returned once after a successful durable transaction and must never be persisted or logged. The ticket is a one-time **confirmation challenge**, not a credential/token authorizing worker pairing. The same installation-scoped `ctx.storage.transaction` vault now has a third allowlisted `admin_actions` key (in addition to `paired` and `pending`); its 100-row bounded registry and fixed per-key JSON budget remain enforced. One pending ticket per worker, competing issues/consumptions and duplicate/replayed proofs fail closed. A consumed ticket leaves an expiry-bounded tombstone. Two distinct workers may hold independent tickets.

**`CONSUMED_FOR_PREFLIGHT` is intentionally NOT authorization**. This library is not wired into `src/index.js` and does not add a public endpoint, private DO RPC, device transport, GitHub grant, active worker lease, pairing or revocation. An Admin ticket is not an atomic cross-repository GitHub PR lock, and it must never be promoted to `prSnapshotVerified`. The existing `BkeWorkerPairingVault.fetch()` remains 404 with no callable RPC.

The protected operation and ticket consumption must execute within one safe transaction or independently prove fail-closed ambiguous-result handling; consuming a ticket in a separate transaction **does not** establish atomic execution of a later action.
